# Engine Warehouse — 포트폴리오 시연 가이드

## 프로젝트 소개

**엔진 자동창고의 입출고 공정과 카메라 기반 로봇 집기 보정을 구현한 Isaac Sim 프로젝트.**

엔진 조립라인 경험을 바탕으로 인라인 파렛트, 롤러 컨베이어, 비전 검사,
수리 복귀 루프, FANUC 로봇, 창고 셀과 외부 반출 파렛트를 구성했다.
핵심은 엔진의 위치·회전 오차를 영상으로 추정하고 집기 경로를 보정하며,
판단할 수 없는 영상에서는 작업을 보류하는 과정이다.

## 3분 내외 영상 구성안

아래 시간은 편집 영상의 권장 분량이며, 공정 사이클타임이 아니다.

| 구간 | 보여줄 내용 | 전달할 메시지 |
|---|---|---|
| 0:00–0:25 | 전체 배치와 입출고 흐름 | 현장 경험을 공정 모델로 옮겼다 |
| 0:25–0:50 | `normal`의 첫 엔진 픽업·안착 | 정상 동작과 성공 기준 |
| 0:50–1:40 | `engine_combined`의 자세 비교와 보정 동작 | 위치·회전 오차를 영상으로 판단하고 보정한다 |
| 1:40–2:25 | `engine_combined_occluded`의 HOLD와 재촬영 | 불확실할 때 멈추고 새 관측으로 재개한다 |
| 2:25–3:00 | 재고 현황·연속 입출고·정량 결과 | 공정 연결과 검증 근거 |

긴 이송 구간은 편집으로 줄이거나 4x로 재생하고, 영상에 배속을 표시한다.
문제 발견·HOLD·그리퍼 접근·안착 순간은 1x로 보여준다.

## 재현 절차

1. `start_editor.ps1`로 실행하고 **Load three-engine demo**를 누른다.
2. **Monitor**를 열어 복구 단계와 재고를 보이게 한다. Advanced/Details는 접는다.
3. **Reset → 케이스 선택 → Apply case → Play** 순서로 실행한다.
4. **Pause to explain correction**을 켠다. 관측 후 자동으로 멈추면 **Engine correction** 창에서 초록 정상 기준과 주황 추정 자세를 비교한다.
   수치는 실제 추정값이고 도식 각도는 5배 확대임을 설명한 뒤 **Continue corrected pickup**으로 재개한다.
   Robot camera는 실시간 시점이며, 테스트용 가림 마스크는 이 뷰에 나타나지 않는다.
5. 성공은 추정 승인만으로 판단하지 않고 Monitor의 **VERIFIED**와 안착 오차로 확인한다.

### 대표 시연 A — 정상

`normal`: 엔진 도착 → 영상 추정 → 픽업 → 창고 안착 → VERIFIED.
정상 좌표에서도 추정 오차가 0이 아닐 수 있음을 수치 그대로 보여준다.

### 대표 시연 B — 엔진 자체의 복합 자세 오차

`engine_combined`: 파렛트는 정상 위치에 둔 채 엔진에 X +20mm, Y -12mm, Z +20mm,
roll +1.5도, pitch -1도, yaw +2도 오차를 주입한다. 이 값은 시험 조건이며 추정 결과와 구분한다.

1. 카메라 이미지와 정상/추정 자세 비교 도식을 보여준다.
2. COMMANDED GRIP CHANGE로 그리퍼 목표가 얼마나 달라졌는지 설명한다.
3. 그리퍼가 엔진 자세에 맞춰 접근하고, 그 자세를 유지한 채 들어 올리는 순간을 1x로 촬영한다.
4. 파렛트를 벗어난 뒤 공중에서 수평을 복원하고 창고에 안착하는 과정을 보여준다.
5. VERIFIED와 실제 기록된 안착 오차로 끝낸다. 자세 불량은 리페어로 보내지 않는다.

설명 예시: “미리 넣은 오차 값을 제어기에 전달하는 대신, 렌더링된 영상으로
자세를 추정해 로봇 접근 경로를 보정합니다.”

### 대표 시연 C — 판단 보류와 복구

`engine_combined_occluded`: 엔진 복합 자세 오차와 영상 가림을 함께 주입한다.

1. HOLD와 로봇 대기를 보여준다.
2. **Retry observation**: 가림이 남아 있으므로 HOLD가 유지되는지 보여준다.
3. **Clear camera mask + retry**: 사용자가 가림을 해제한다.
4. 새 영상의 승인 → 보정 집기 → VERIFIED를 보여준다.

설명 예시: “로봇이 가림을 직접 치우는 기능은 아닙니다. 사용자가 가림을
해제한 뒤 시스템이 새 영상을 확인하고 작업을 재개합니다.”

## 검증 기록과 재생성

2026-11-02에 2026-10-26 저장 결과를 집계했다. 이번 문서 갱신에서 시뮬레이션을 다시 실행하지 않았다.
케이스별 결과와 원본 파일 SHA-256은 [VALIDATION_SNAPSHOT.md](VALIDATION_SNAPSHOT.md)에 있다.
전체 17개 케이스와 시각화 UI 확인용 3개 케이스는 별도 시험 묶음이다.
각각 한 번의 기록이며, 둘을 더해 성공 확률로 제시하지 않는다.

프로젝트 루트에서 다음 명령으로 로컬 결과 보고서를 다시 만든다.

```powershell
& C:\isaacsim\kit\python\python.exe projects/engine-warehouse/build_portfolio_report.py
```

출력: `outputs/portfolio-validation.md`. 원본 결과 파일이 없으면 새 테스트를 실행해 확보해야 한다.
이 스크립트 자체는 시뮬레이션을 실행하지 않는다.

### 자세 추정 방식과 오차의 구분

- 파렛트 위치/회전 케이스: 고정 장면의 학습 기반 RGB 추정.
- 엔진 자체의 XYZ/roll/pitch/yaw 케이스: 고정 작업영역의 RGB-D 기하 정합.
- RGB 모델 별도 검증: 학습 343개, 선택 32개, 최종 검증 32개. 최대 X/Y/yaw 오차는 1.362mm / 1.115mm / 0.187도.
  출처: `outputs/pickup-perception/warehouse-evaluation.json`의 2026-10-26 기록.
- 위 RGB 수치를 엔진 RGB-D 추정 정확도라고 소개하지 않는다.
- 결과표의 안착 오차는 동작 후 위치 오차다. 영상 추정 오차 또는 힘 센서 측정값이 아니다.

### 공정 대기 개선

동일한 명목 재생 경로·속도 조건에서, 출고 컨베이어 이동과 로봇의 다음 작업을
겹치도록 변경해 모델 시간 **491.33초 → 437.42초 (약 11% 감소)**를 기록했다.
카메라 촬영·경로 계산의 실제 소요 시간은 포함하지 않는다.
이번 비전 보정 시연 전체의 실시간 사이클 성능으로 제시하지 않는다.
상세 조건: [MULTI_ENGINE_PLAN.md](MULTI_ENGINE_PLAN.md).

## 구현 범위와 설명 시 구분할 점

- E1은 영상 추정에 따라 보정한다. E2/E3는 기존 재생 경로를 사용한다.
- 외관 검사 OK/FAIL 및 수리 완료는 시나리오로 주어진다. 실제 부품 불량 검출 모델은 아니다.
- 창고 영상 모델은 고정 장면에서 검증했다. 조명·외형 변화나 실기 일반화는 검증하지 않았다.
- 영상 가림 판정은 어두운 영역·학습 영상과의 차이에 대한 기준을 사용한다.
  모델의 추정 신뢰 확률로 설명하지 않는다.
- 파지는 이상적인 운동학적 구속이며 접촉력·하중 검증은 범위에서 제외한다.
- 완전한 경로의 연속 충돌 검증이나 실제 설비 적용을 입증하는 결과는 아니다.
