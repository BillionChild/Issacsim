# 엔진 자동창고 시뮬레이션 설계

## 진행 방식 수정 — 2026-09-28

설비별로 모델 후보를 제시하고 사용자가 선택한 뒤 적용한다. 기본 형상으로 대체하는 것도 임의로 결정하지 않는다. 모델·치수·배치가 확인된 설비만 구현하고 결과 확인 후 다음 설비로 넘어간다. 아래 기본 형상 우선 전략과 좌표·툴 구성은 사용자 확인 전까지 제안으로 취급한다. 첫 단계는 입고 컨베이어 모델 선정이다. 세부 절차는 구현 계획의 사용자 지정 진행 방식을 따른다.

## 목적과 확정 요구사항

엔진 조립라인 경험을 바탕으로 제조 물류 시뮬레이션 포트폴리오를 만든다. 완성 엔진은 공정 인라인 파렛트로 입고된다. 산업용 6축 로봇 한 대가 엔진만 들어 창고용 외부 파렛트로 옮기고, 이어 외부 파렛트와 엔진을 함께 창고 셀에 적재한다. 보호커버 공정은 사용하지 않는다. 실제 공장 검증 전까지 가상 설비 시뮬레이션으로 소개한다.

## 구현 순서와 첫 범위

첫 단계는 Isaac Sim에서 열고 검사할 수 있는 정적 USD 장면이다. 입고 컨베이어, 인라인 파렛트와 엔진 대체 형상, 위치 결정 핀이 있는 외부 파렛트, 외부 파렛트 작업대, 창고 셀 하나, 로봇 설치 위치 표시, 툴 교환 위치 표시를 만든다. 단위는 m, Z-up을 사용한다. 기존 projects/franka-cell 실습은 유지하며 신규 코드는 projects/engine-warehouse에 둔다.

기본 형상을 먼저 쓰는 방식은 자산 다운로드 없이 장면 구조를 검증할 수 있어 채택한다. 처음부터 상세 CAD와 실제 로봇을 통합하는 방식은 모델 정리와 제어기 설정이 선행되어야 하므로 다음 단계로 둔다. 기존 Franka를 중량물 로봇 대용으로 사용하는 방식은 실제 설비 성능으로 오해될 수 있어 채택하지 않는다.

정적 장면 이후 산업용 로봇과 툴을 선정하고 한 사이클 동작, 복수 셀과 재고 관리, 이상 상태 인식 및 복구 순서로 확장한다. 첫 장면은 AI·파지·이송 성공이나 도달성 검증 결과가 아니다.

## 장면 구조

- /World/EngineWarehouse/Infeed: 컨베이어와 인라인 파렛트.
- /World/EngineWarehouse/TransferStation: 외부 파렛트 안착 작업대.
- /World/EngineWarehouse/Storage: 보관 셀 1개.
- /World/EngineWarehouse/RobotStation: 로봇 설치 위치 표시.
- /World/EngineWarehouse/ToolStation: 엔진 그리퍼와 파렛트 포크의 교환 위치 표시.
- /World/EngineWarehouse/Loads: 식별 가능한 엔진 및 외부 파렛트.

엔진과 두 종류의 파렛트는 별개의 prim으로 유지한다. 모델 원점과 파지·안착 기준점을 명시해 상세 모델로 교체해도 공정 좌표를 추적할 수 있게 한다. 첫 장면의 치수와 배치는 설명용 가정이며 실제 도면이나 도달성 보증이 아니다. 실행 안내에 가정값을 표로 남긴다.

## 후속 동작의 설계 계약

상태 흐름: 입고 감지 → 정지·고정 → 외부 파렛트 준비 확인 → 엔진 집기 → 엔진 안착 확인 → 빈 셀 예약 → 툴 교환 → 외부 파렛트와 엔진 집기 → 셀 적재 확인 → 재고 확정.

엔진 ID, 외부 파렛트 ID, 셀 ID를 연결한다. 셀은 EMPTY, RESERVED, OCCUPIED, BLOCKED 상태로 관리한다. 예약과 실제 적재 확인을 구분하고 오류 시 재고를 성공 상태로 갱신하지 않는다. 출고와 빈 파렛트 순환은 입고 사이클 검증 이후 별도 설계한다.

툴 체인저로 엔진 그리퍼와 파렛트 포크를 교환하는 구성을 초기 가정으로 둔다. 실제 로봇 선정 시 엔진·외부 파렛트·툴 중량, 무게중심, 손목 허용 모멘트와 모든 목표 자세의 접근·이탈 경로를 확인한다. 기종 선정 전에는 중량이나 사이클타임의 현실성을 주장하지 않는다.

## 이상 대응 확장

1. 입고 위치 편차: 위치 추정 후 허용 범위 내 집기 목표 보정, 초과 시 보류.
2. 엔진 안착 불량: 입고 차단, 검증된 조건에서 재안착 시도.
3. 셀 점유 정보 불일치: 해당 셀 보류 후 대체 셀 예약.
4. 이물질: 이송 보류 및 제거 요청. 휴머노이드의 가벼운 이물질 회수는 별도 확장 과제이며 첫 단계에 포함하지 않는다.

규칙 기반 처리와 학습 모델의 역할을 기록한다. 센서 기반 추정값과 시뮬레이터 정답값을 분리하고 정답값을 AI 출력처럼 사용하지 않는다. 복구 횟수 제한과 사람에게 인계할 조건을 둔다.

## 첫 단계 완료 기준

- 생성 스크립트와 실행 설명으로 동일한 장면을 재생성할 수 있다.
- USD가 열리고 필수 prim, m 단위, Z-up, 서로 다른 파렛트가 확인된다.
- 엔진이 입고 파렛트 위에 있고 외부 파렛트와 창고 셀은 비어 있다.
- 위치 결정 핀과 엔진 형상은 설명용이며 실제 기계 결합을 검증했다고 표시하지 않는다.
- 기존 실습 파일과 사용자 변경을 보존한다.
- GUI로 직접 확인하지 못했으면 구조 검증과 화면 검증 여부를 분리해서 보고한다.

## 포트폴리오 지표

후속 동적 단계에서 입고부터 셀 적재까지 걸린 시간, 툴 교환 시간, 대기 시간, 시간당 처리량을 기록한다. 이상 대응 단계에서는 오류 종류별 감지·복구 성공률, 복구 시간, 사람 인계 비율을 측정한다. 측정값과 설정한 가정값을 구분한다.
